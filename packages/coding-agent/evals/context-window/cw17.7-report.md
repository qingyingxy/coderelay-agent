# CW.17.7 Repeated Real-Repository Evaluation

## Decision

Keep `summary` as the default context-management mode. The hard-cut group completed every repository repair and recovered every long-range value, but its strict protocol pass rate was lower and its input/cost overhead did not meet the default-switch gate.

## Protocol

- Task Set: `context-window-real-repository-v1`
- Repositories: QuixBugs `lis`, `rpn_eval`, and `sieve` at revision `4257f44b0ff1181dedaedee6a447e133219fcebf`
- Groups: A=`summary`; C=`windowed + Workflow Snapshot + Notes + History`
- Model: `qingyingxy/gpt-5.6-terra`
- Thinking: `medium`
- Repetitions: 3 per task and group, 18 runs total
- Execution: strictly serial, Provider retries disabled
- Per run: 3 context boundaries, 3 disk-level AgentSession resumes, one real source repair, one hidden repair, and one independent verifier pass
- Cost: official OpenAI short-context pricing with a `$3.00` total development-evaluation cap

Every fixture is pinned by a repository digest. The original baseline must fail, the reference repair must reach the controlled hidden failure, and the reference plus hidden marker must pass before a paid run is allowed.

## Failure Analysis

All six strict C failures had exactly one failed check: `probe-called-once`. They made one redundant call to the immutable `benchmark_probe` after the first hard cut; no repository mutation, memory loss, verifier failure, lineage error, resume failure, or active-context exclusion failure occurred.

The persisted seed exposed the cause. `Current objective` used a head-only 256-byte field projection. The controlled boundary prompt placed its post-cut continuation at the end, so the seed retained the boundary header and padding but omitted `reply exactly WINDOW_1_READY`. Three C runs inferred the right continuation; six repeated a harmless probe before continuing.

The Workflow projection now retains both the beginning and end of a long objective, with an explicit middle ellipsis. A deterministic regression verifies that the task identity and trailing continuation instruction both survive.

## Conclusion

The hard-cut architecture is functionally viable on this task set: full history, Snapshot authority, Notes, History, three-window recovery, and real code repair all worked. It is not ready to become the default because the original strict pass rate was 33.3%, input rose 28.0%, cost rose 5.1%, and the post-fix sample is too small. CW.18 should keep `summary` as the global default and treat `windowed`/`hybrid` as opt-in until a repeated post-fix matrix demonstrates stable boundary adherence.
