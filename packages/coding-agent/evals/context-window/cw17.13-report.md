## Implemented Changes

`benchmark_evidence_status` projects current-branch consumption receipts and matching tool-result entry IDs.
It does not return the continuity token or repair marker, consume evidence, or equate a claim with a durable result.
Both groups receive the tool and the same resumed-phase instruction: inspect availability before a one-shot call;
recover closed evidence from retained context, Notes, or History. Model-selected Notes and retrieval remain open.
This changes both tool availability and prompt policy; it is not an isolated tool-only experiment.

The existing one-shot guards still reject duplicate attempts. Durable `benchmark-phase` entries separate task
phase from physical compaction count. This is necessary because normal summary retention may need no compaction.
The new `--summary-keep-recent-tokens` flag applies on initial creation and every disk resume. Its benchmark
default remains the explicit stress value 1; the new comparison passes 20000. No production default changed.

At each scheduled boundary, summary uses the existing compaction preparation logic. If there is no prefix to
summarize, it records `actualReason=retained` and still performs the planned disk resume. Evidence retention is
reported independently in `evidenceExposure`; a summary that legitimately retains original evidence does not
fail merely for doing so. `crossBoundaryRecoveryExercised` requires both probe and verifier entries to leave
active context plus all three resumes. A passing recovery score with this flag false is continuity evidence,
not evidence of retrieval after exclusion. C must still produce three Snapshot-backed hard cuts.

Current protocols are `matched-v5` and `autonomous-v3`. Historical reports retain their original scoring and names.

## Conclusion

The benchmark now gives the model a durable, inspectable tool-state interface while preserving one-shot guards.
Observed duplicate attempts were zero in this follow-up. Normal retention removed the earlier short-task
continuity failures in these three A examples without requiring compression; C also passed, with higher recorded
cost and time under mandatory cuts. This supports retaining the current default while gathering longer-task
evidence, not deploying a routing rule from six short trials.

Long-task validation is still unexecuted. The task assets are verified, but Docker/Pier and runner integration
remain prerequisites. No production routing or general-purpose one-shot tool registry was implemented; changes
are scoped to the real-repository evaluator and its regression tests.
