# CW18.11: Minimal context handoff

Date: 2026-09-06

## Scope

Keep Session History, Notes and Workflow Snapshot. No requirements state
machine, summary model, extra agent or semantic submission gate was added.

The Direct adapter previously had no model-facing progress write path. With
explicit user approval, `new_context` now accepts optional `handoff` text
(1-2000 UTF-8 bytes). It replaces the running Direct root Task's existing
`description` through a persisted event. The original Workflow request and old
event history remain available. Task and verification statuses are unchanged.
This is an agent-reported current brief, not proof of successful verification.

The normal context checkpoint includes that description in Snapshot. Seed
projection places it and unresolved/missing verification records ahead of task
and attempt details, while retaining objective, constraints and next action.
Notes remain for durable decisions, constraints and discoveries. The Pier
submission prompt asks the model to resolve unchecked work and compare local
evidence with original requirements and affected regressions.

## Free verification

- 154 targeted tests passed across the final runs (13 files; the four-case
  token-budget file was rerun after aligning the reminder wording).
- Faux continuation with and without handoff each uses three model requests:
  request cut, request fixture verification, final response. There is no
  additional summary request.
- Tests cover handoff visibility, verification before the scripted final reply,
  unchanged executing status after handoff, event replay, two successive cuts,
  replacement of old progress, original objective retention, empty Notes,
  soft-warning handoff, and rejection of empty/oversized/unsupported handoffs.
- Projection tests cover failed checks under a bounded seed, requirements
  without results, and avoiding a finalize suggestion when verification failed.
- Existing Pier budget/repair, recovery, event log, controller and Notes tests
  remain passing. No paid provider or real Docker trial was run.
- `npm run check` exited 0, including type/import/lock/browser checks, but its
  Biome write pass reported access denied on unrelated `evaluation/protocol.ts`.
  A subsequent full read-only `biome check --error-on-warnings .` passed for
  1071 files. npm also reports the existing unsupported `min-release-age` option.

## Limits and next measurement

Faux responses prescribe the next check; they do not establish that a real
model chooses sufficient tests or enumerates all original requirements.
The handoff is optional and only written on a model-requested Direct cut.
Forced cuts retain the last recorded state; they do not synthesize a new brief.
Plan/conversational calls omit this parameter. Seed details may still be
omitted at tight byte limits, with the existing truncation marker.

The handoff is capped at 2000 bytes; the projection budget remains 12000 bytes.
Tool-schema/prompt text and the brief add tokens despite no new summary request.
Actual token/cost change has not been measured with a real model. A matched
trial should inspect visibility, checks before submission, unsupported success
claims, requests/tokens, and requirements never recorded in the first place.
