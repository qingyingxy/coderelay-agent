# CW18.13: Normal execution and repair without budget-driven stages

Date: 2026-09-06. Free validation only; no paid model calls or host commit.

## Scope

Execution policy is now `isolated-fixed-direct-v4`. Changes are confined to
the Pier evaluation adapter, its tests, smoke driver and documentation.
Agent core, Window, Snapshot, Notes, History and the existing optional
`new_context.handoff` are unchanged. No platform, routing policy, summary call
or requirements state machine was added.

Removed the four-request closing reserve, budget phase transition, tool
filtering/locking, budget prompt injection, dedicated `container_repair`,
single-repair limit and submission-triggered disabling of context maintenance.
Verification failures now leave ordinary execution and memory tools available.
The model repairs with `container_exec` and retries `container_submit`.

Submission still requires `git diff --check` and the model-selected verification
command to pass before committing. Retrying with a different verification
command is rejected. Attempts retain the command and returned evidence.
Any subsequent `container_exec` conservatively invalidates current submission
status, including read-only or failed shell commands; old evidence remains in
the attempt log, and fresh submission is required.

The evaluation caller still accounts usage and enforces its authorized cost,
request and timeout limits. This guard neither changes prompts/tool availability
nor reserves closing requests. Timeout stops subsequent model dispatch and
cancels the session; cancellation observed after verification prevents starting
a commit. An already-running bridge command may finish before cancellation.
No external platform integration was implemented.
