# CW.18.6: Timely warnings and reserved submission

Date: 2026-09-06. Free implementation and regression checks only.

## Changes

- AgentSession checks hard-window budgets at the existing prepare-next-turn
  boundary after tool results are persisted. It includes the estimated size of
  newly returned tool output. A soft warning enters the steering queue before
  the next provider call; a hard limit schedules a Snapshot-backed cut at that
  safe boundary. Existing explicit cuts take precedence. Terminal provider
  errors do not trigger a new warning/continuation after the run has failed.
- Pier probes container command availability before any paid request and saves
  `capabilities.json`. Git must be present. Both groups receive the actual probe
  results and editing guidance, including the incompatibility between
  apply_patch syntax and git apply/patch. No container packages are installed.
- The fixed execution protocol is now `isolated-fixed-direct-v2`. Two provider
  requests and their worst-case cost are reserved for submission and the final
  response. Per-request notices persist remaining capacity and phase and are
  reinjected after context cuts. Either the request or dollar constraint can
  trigger submission; the phase cannot revert to implementation.
- During submission only `container_submit` is advertised and executable.
  It runs a whitespace check and a bounded model-selected local verification,
  then stages and commits the disposable task repository only on success.
  Failures are tool errors and persist as failed submission evidence. A normal
  final reply without successful submission is `submission_incomplete`.
- Auxiliary summaries cannot spend the reserved capacity. After successful
  submission, automatic context maintenance is disabled for the final reply.
  The official verifier remains separate and unchanged.

## Validation

48 focused tests passed across Pier budget/session regressions, hard context
windows, context-management statistics, context-window evaluation, and isolated
Workflow routing. These use Faux providers and simulated container replies.
Coverage includes:

- Large tool output causing a soft warning or a Snapshot-backed hard cut before
  the next call in a continuous tool loop; original tool results remain durable.
- No warning-triggered extra request after a terminal provider failure.
- Request-count and dollar-based submission reserves, refusal of insufficient
  initial budgets, and auxiliary deferral without consuming reserved requests.
- Original instruction A/C runs, Notes/History and Snapshot preservation,
  submission with exactly three available requests, and active rejection of
  attempted implementation after submission mode begins.
- Failed verification prevents commit; failed commit and missing submission
  cannot count as runtime completion. Notices and capability guidance reach
  model context; official success remains unknown until independent grading.

`npm run check` exited 0, and the additional Pier TypeScript check passed.
The root check still emitted the existing Biome access-denied diagnostic for
`src/core/evaluation/protocol.ts` and npm `min-release-age` warnings; this was
not warning-free validation. The preparation-only config validator also passed
with zero paid calls, reporting the two-request reserve and $0.624 minimum.

## Limits and budget

This is not a paid model-quality result or a Docker end-to-end submission test.
The model selects local verification and can choose inadequate checks; a commit
does not certify task correctness. The shell tool remains a trusted model command
interface in the disposable container, not a semantic command firewall. Two
reserved requests do not guarantee that the model finishes within them, nor do
they guarantee time or service availability.

The new minimum is one implementation request plus two submission requests.
At the previous configuration, each full reservation is $0.208 and the initial
minimum is $0.624. The remaining aggregate estimate is $0.3970816, so that
configuration must not be relaunched under the current remaining authorization.

No paid calls were made. Cumulative estimate remains $5.6029184 of $6.
CW.18.3 through CW.18.5 remain unchanged historical reports; v1 and v2 must not
be pooled as the same execution protocol. Next validate v2 submission against a
free disposable-container fixture before planning another paid long-task run.
