## Readiness Finding

Importing persisted events and calling `enableWorkflowTracking("direct")` does
not recreate the active Direct adapter used by a running task. The cut obtains
its Snapshot from `_activeWorkflowAdapter` / `_planWorkflowRuntime` or the latest
Direct context provider. Those runtime objects are absent in this import path.
Consequently `requestContextWindow("manual")` falls back to a conversational
Seed with no snapshotEntryId/workflowId. The probe records
`fullStrategyReady: false`; it must not be dispatched as the real C treatment.

This is a limitation of the proposed evaluator restart/import method. It is not
evidence that the Snapshot-backed cuts previously exercised in live sessions
failed. A successful cut record alone would have hidden this mismatch.

## Next Implementation

Keep production memory architecture unchanged. The controlled evaluator needs
a lifecycle-aware boundary: recreate the common history through the normal
session execution path with cached tool results and scripted prior responses,
or use an explicitly supported runtime restoration entry. At the common point,
assert that C has an active Direct context provider before requesting handoff.
Do not silently replace missing state with a manually invented task summary.

Before any paid continuation, require equal pre-maintenance message hashes,
equal repository state, exactly one maintenance event, a Snapshot-backed C
boundary, no unmatched calls and demonstrable post-boundary execution. Separate
scripted plumbing success from real task success. Generate any real summary/
handoff only from pre-boundary evidence and include that generation in cost.

The current exported checkpoint is reusable; no additional paid run, new
production state structure, manually supplied task hint or fabricated Snapshot
was added in this step.
