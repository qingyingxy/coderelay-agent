# CW18.16: Paired real-model handoff prompt probe

Date: 2026-09-06. Synthetic inputs only; no Docker task, production memory
change, independent summary model or host commit.

## Protocol

The user approved a small real-model comparison after CW18.15's scripted
regressions. The evaluation reuses the previously authorized $2 per-run
estimated ceiling. Limits live exclusively in the evaluation caller.
Provider/model: qingyingxy / gpt-5.6-terra; medium reasoning; 40000 context,
2000 maximum output tokens; 48 maximum requests; 1800 seconds; no retries.
Estimated rates per million input/output/cache-read/cache-write tokens are
$2/$12/$0.2/$2.5, as previously approved, not independently verified billing.

Eight matched pairs use two feature names: safe_bulk_upsert transaction rollback
and resumable_download checksum mismatch. Each feature has two pending-work
repetitions, one targeted-verification control and one explicit user-cancellation
control. Each arm performs three replacements. Arm order alternates per pair.
The original and new handoff parameter descriptions and Seed verification
guidance are pinned in `plan.json`; both additions from CW18.15 change together.

This is a prompt-only simulation of successive brief replacement, not actual
SessionManager cuts. The model emits the existing `new_context` tool argument.
Each request contains only the prior brief and current synthetic observation;
earlier messages are discarded, Notes are empty and History retrieval is not
available. A missing optional argument preserves the old brief, as in production.
The runner never reinjects omitted ground truth. It does not execute tests,
submit code or establish repository correctness.

The rubric was saved before dispatch. At every pending cut, the feature must
remain unverified or explicitly require a targeted check. In the controls, the
second and third briefs must acknowledge E2 targeted success or U2 cancellation
without retaining the obsolete blocker. Silent deletion is ambiguous, not
credited as evidence-based resolution. Any earlier loss counts even if the
feature later reappears. A manual semantic review is required; keyword presence
alone is not scored as success. Review is by the implementing assistant, not an
independent blinded judge.

## Validation And Startup

Three free focused tests passed: omitted content is not restored from ground
truth; optional omission preserves the previous brief while invalid replacements
are rejected; the new tool schema matches production and paired observations
are identical. `npm run check` exited 0, including type checks. Its Biome write
pass reported the preexisting access error on unrelated `evaluation/protocol.ts`;
full read-only Biome passed 1073 files. Existing npm min-release-age warnings
remain. `git diff --check` passed.

The first startup failed before dispatch because sandboxed credential access
returned unavailable. A credential-status-only diagnostic confirmed that the
same model/auth was available outside the sandbox. The temporary diagnostic was
removed. The paid run uses a fresh artifact directory; this is not a repeated
model trial. The dry plan and zero-request startup plan remain in the adjacent
`handoff-micro-20260906-dry` and `handoff-micro-20260906-real` directories.

## Limits

Short explicit synthetic observations make this easier than CW18.14's long
coding task. There are only four pending chains and two chains per control per
arm; their cuts are dependent, not independent trials. No model seed is fixed.
These results cannot estimate long-task failure rates, prove no omissions,
separate the effects of the two prompt additions, or justify a routing policy.

## Next Step

Keep the minimal existing guidance and architecture. Freeze this result as a
small behavioral baseline, with no demonstrated old/new quality difference.
Before any further paid comparison, prepare free replay fixtures from the
CW18.14 evidence: multiple pending requirements, long tool outputs, partial
verification and plausible final-suite success. Verify that the fixture and
scorer can expose an intentionally omitted item. Do not reinsert the answer in
every window. Only then decide whether another bounded comparison is informative.
Routing and additional memory machinery are not justified by this result.
