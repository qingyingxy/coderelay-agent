## Integration

`runPierSession` accepts an optional controlled checkpoint. The real Python
entry point exposes `--controlled-checkpoint`; preparation freezes the selected
arm's session, manifest and repository descriptor in the output directory.
It checks the prefix hash, original instruction and selected task base before
dispatch. Docker execution checks HEAD, tree, clean worktree and isolation
probes, then creates the audited pre-edit branch. It never replays recorded
shell commands to reconstruct arbitrary state. Post-edit checkpoints are not
supported by this initial restoration recipe.

`PierControlledReplay` supplies seven recorded assistant responses and thirteen
cached tool results through the ordinary SDK execution path. Those responses
bypass provider dispatch and accounting. Tool call IDs, arguments, result IDs
and canonical pre-maintenance messages must match the frozen source. C thus
has a live Direct Workflow at the boundary, without importing fabricated state.

A uses the SDK compaction primitives at the settled tool boundary, resolving
model authentication through ModelRuntime. Its summary calls use the regular
budget wrapper. C's first live request receives a generic instruction to prepare
a handoff from existing history and call new_context before repository work.
The instruction is recorded separately and contains no implementation hints or
hidden test information. The normal new_context tool creates the Snapshot cut.
The handoff request is counted, even though the cut itself needs no summary call.

After maintenance, execution and submission use the existing Pier bridge and
submission protocol. New execution/submission before maintenance is rejected;
missing or multiple boundaries mark the controlled runtime incomplete. Existing
noncontrolled behavior, Agent production code and memory architecture are unchanged.
This is a distinct controlled protocol, not a natural-window benchmark.
