## Workload

Each run used a fresh code workspace and the same controlled sequence:

1. Read `SPEC.md` and the initial `src/router.mjs` stub, preserve durable constraints, and call an exact-value probe.
2. Cross the first context-reduction boundary and destroy/recreate the AgentSession from the same Session JSONL.
3. Implement the resolver and run an isolated verifier that exposes one hidden repair requirement.
4. Stop before repair, cross the second boundary, and destroy/recreate the AgentSession again.
5. Recover the exact old failure, repair `src/router.mjs`, run the verifier, and emit strict final JSON.
6. Let the runner independently execute the hidden verifier again and check protected-file hashes.

The initial verifier failure was genuine and persisted as a tool result:

```text
HIDDEN_REPAIR_REQUIRED: export const repairMarker must equal "omega-41"; received undefined
```

The marker was absent before the second boundary. Both model-requested and independent repair verification later passed.

## Decision

The combined CW.17.3 and CW.17.4 evidence now covers the requested lifecycle risks and demonstrates one complete hard-cut coding path. It still does not justify changing the default from `summary`: the real coding sample contains one synthetic repository task and one run per strategy, and C cost 5.6% more than A in that sample.

Keep `summary` as the default. Before a default-mode decision, add broader repositories, longer tasks, repeated runs, injected process termination between Snapshot and boundary commits, and explicit adversarial branch-retrieval cases.
