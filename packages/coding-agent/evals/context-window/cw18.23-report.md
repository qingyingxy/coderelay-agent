## Eligibility Correction

`run_pier_real.py` previously accepted any recorded maintenance boundary as
memory-quality evidence. It now additionally inspects the final Session branch
and requires a new `container_exec` call followed by its matching tool result
after a boundary. `memoryContinuation` retains per-boundary timestamps,
assistant-turn counts, execution-call/result counts and result entry IDs.

End-of-task summaries, text-only continuations, submission alone, old unmatched
tool results, abandoned branches and missing/ambiguous Session evidence do not
qualify. Only the current single-session trial layout is supported; ambiguous
multiple-session layouts are conservatively ineligible.

This is a minimum evidence filter, not a semantic judge. A read-only command
or failed command can pass it. Review the referenced commands to confirm
substantial implementation, debugging or verification after maintenance.
Final independent grading remains separate; eligibility does not mean success.
Incomplete/failed/ineligible runs remain in the overall results denominator.
