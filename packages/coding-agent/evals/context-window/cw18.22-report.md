## Boundary Timing

Session records in both 128K runs contain no `context_window` or `compaction`
entries. Both runner reports correctly mark `memoryBoundaryExercised: false`
and `memoryQualityEligible: false`. Neither provides evidence of recovery.

The policies were intentionally unchanged. With the existing reserve cap,
C's 64K soft/hard thresholds were 38400/51200; at 128K they are 96000/112000.
All five previous C cuts followed soft warnings at approximately 39K-45K.
This time the entire C trajectory fit below the new warning threshold.

A still checks automatic compaction at different lifecycle points from C.
Its sole 64K compaction was after the final answer, with no subsequent task
execution. Increasing both window sizes does not make those policies symmetric.

The observed reduction from five C cuts to zero is consistent with removing
the early warning pressure. It does not establish that the old trajectory
would have been identical without cuts, or quantify how much repeated reading,
different implementation choices and sampling contributed to the old cost.

## Independent Failures And Local Checks

A 128K failed only `test_cli_upsert_safe_mode`: CLI exit status was 1 rather
than 0. The verifier output does not expose the underlying CLI error, so no
more specific root cause is claimed here. A added `tests/test_safe_import.py`,
ran the full local suite, discovered four missing CLI documentation examples,
fixed them and reran successfully before submission.

C 128K failed six checkpoint cases: rollback, commit, nested checkpoint
handling, nested savepoints, inactive-after-rollback and inactive-after-commit.
The traces show missing savepoints. C added implementation and documentation
changes but no test file; its selected final local checks passed 225 tests.
The independent full-suite log additionally reports four missing documentation
examples for disable-safe-import, remove-import-invariant, list-import-invariants
and validate-import-invariants. These dynamic cases are outside the pinned
1038 preservation list. Thus 1038/1038 must not be described as a clean full suite.

The omissions persisted without any cut or summary. They cannot be attributed
to handoff loss in these runs. Differences in selected verification scope are
visible; attributing them causally to a strategy requires repeated evidence.

## Interpretation And Next Step

128K is a useful next experimental setting: this task no longer repeatedly
crosses the C warning threshold, and both new trajectories used fewer requests
and lower estimated cost than their respective 64K observations. Single trials
do not establish stable success rates, superiority or causation. In particular,
A's higher score here is not evidence that summarization recovered better:
no summary occurred.

Keep the current memory architecture unchanged. For a recovery comparison,
select a genuinely longer task at this window size, with substantial execution
after a recorded boundary and independent final grading. Report maintenance
timing and resumed actions, not just boundary presence. An end-of-task summary
must not qualify as recovery. No further paid run or prompt patch was performed.
