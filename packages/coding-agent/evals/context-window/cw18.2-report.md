# CW.18.2 Budgeted Real-Model Entry

Date: 2026-09-06. Authorized scope: implement the real-model entry and budget
controls, then validate without paid model requests. No paid trial was executed.
The prior recorded estimate remains $5.1244976; new actual model expenditure is $0.

## Implementation

`run_pier_real.py` validates explicit provider, model, strategy, token/request/time
limits and rates, and exports the pinned task into a fresh output tree. Default
mode prepares only. `--execute-paid` is required to launch one trial; the Pier
adapter also requires the explicit boolean gate and matching model identity.
Credentials remain in the existing Pi configuration, outside the task container.
No matrix or automatic retry/resume is implemented by this entry point.

`pier-real-session.ts` creates the actual Pi SDK session with empty host resources
and only remote repository execution plus memory tools. Both A and C use medium
thinking, normal 20000-token summary retention, and 16000 reserve tokens. A uses
summary context management; C uses windowed context with direct Workflow tracking
and the new-context tool. Both receive the original instruction once. Requested
model capacity is checked before the first model call.

`pier-budget.ts` wraps the SDK's shared stream function, including compaction and
branch-summary requests. Each request reserves a full configured context at the
largest input/cache rate plus the output cap before dispatch. Known successful
usage settles that reservation using supplied rates. Errors or absent usage keep
the reservation and stop subsequent calls. Requests are serial; session/provider
retries are disabled. Request count includes summaries. Reasoning is not charged
again on top of output tokens.

The budget is conservative local accounting, not an enforceable service billing
cap. Rates and provider token reporting need confirmation before paid execution.
The limit applies to one trial; multiple invocations need a separately reviewed
aggregate budget. Synthetic test rates are not proposed qingyingxy prices.

`budget.jsonl` preserves reservations before requests. Session JSONL, events,
prompt hashes, effective tool names, SDK status and usage estimates are retained.
Timeout, budget/provider stop and incomplete replies are not runtime completion.
Independent grader output is retained separately in `report.json`; a normal
assistant final response is not evidence of task success. Missing SDK evidence
after a process failure is retained as missing, not counted as free success.

## What Remains Unverified

actual billing have not been exercised by this change. Free SDK tests and the
existing faux Docker adapter validate separate parts of the path; they do not
substitute for an end-to-end real-provider pilot. Neither long-task success nor
the effectiveness of summary/Workflow/Notes/History or routing is established.
