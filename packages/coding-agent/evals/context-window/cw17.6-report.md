## Defect Found And Fixed

The loader already ignored an incomplete final JSONL line, so the first reopen appeared successful. However, the next append was written directly after that unterminated fragment. The fragment and the new record then formed one malformed physical line, causing the new record to disappear on the second reopen.

`SessionManager` now inspects the final byte when opening an existing file. If the file does not end in `\n`, the first subsequent append writes one separator newline before the next JSON record. The damaged fragment remains available for forensics, while all later records remain independently parseable.

Every scenario also verified that continuation did not invent a missing Snapshot or boundary and did not duplicate a committed boundary.

## Recovery Semantics

- An incomplete physical JSONL line is treated as an uncommitted tail record.
- Every complete record before it remains authoritative.
- A complete Snapshot without a complete ContextWindowEntry does not advance the active window.
- A complete ContextWindowEntry remains the hard-cut commit marker even if the first later message is incomplete.
- History continues to search the complete current-branch prefix.
- Resume preserves the malformed fragment and separates future appends with a newline.
