## Failure analysis

The four official feature failures are all safe upsert cases: API success,
validation failure, strict validation failure, and CLI safe upsert. Their
traces report a missing SQLite savepoint during release or rollback; strict
mode consequently exposes the savepoint error rather than the required
validation wording. Earlier development checks also encountered savepoint
issues, but the submitted implementation still fails these upsert paths.

Four pinned preservation IDs fail: two CLI commands lack help text
(remove-import-invariant and list-import-invariants), and two SQL tracer/count
tests observe a changed table-enumeration query. The patch adds
`name NOT LIKE '_sqlite_utils_%'` to that query.

The raw suite additionally reports six undocumented-command failures, outside
the pinned scoring whitelist. It reports 10 failures in its first suite and
4 feature failures in the second, while the official whitelist counts only 8.
The grader deliberately scores pinned IDs; preserve both raw and official
counts rather than silently changing denominators. The help tests use positional
parameter IDs such as command3/command4, so their classification as preservation
tests does not prove the exact same command object was tested at the base commit.

The model-selected local suite omitted documentation/help and tracer/count
checks and did not cover safe upsert in its added regression file. Therefore
the successful local check never opened the reserved repair stage. The observed
limitation is verification coverage plus implementation defects, not evidence
that the repair tool failed. No hidden tests or retrospective repairs were fed
back into this trial.

## Next work and limits

Before another paid run, free-test a general submission verification policy
that includes the repository's available regression suite and checks coverage
against the original requirements. Separate broader verification time from
model request capacity. Do not add hidden failure answers to the unchanged
benchmark prompt or retrospectively rescore this patch as an original success.

The bounded repair branch still has only the free evidence in CW.18.9. One
real-model v3 delivery cannot establish A/C superiority, reliable recovery,
or a routing policy. Keep summary as the default and retain failed trials.
