# CW18.32: Searching for tasks with observed long trajectories

Date: 2026-09-07. Read-only public-source research and local metadata analysis.
No model trial, dependency installation, container execution or paid request.

## Main Finding

Found a concrete FeatureBench task with a published trajectory exceeding 128K
request input, rather than merely a complex description or large cumulative
token count:

`pandas-dev__pandas.82fa2715.test_all_methods.c74b49a1.lv1`.

Original task title: **Implement GroupBy Statistical and Transformation Operations**.
It requires a broad set of Pandas GroupBy operations: statistical moments,
correlation, extrema indices, reductions, cumulative operations, filling,
shifting, ranking and group numbering, with dtype/index/missing-value behavior.

The public run used OpenHands with Qwen3-Coder-30B-A3B-Instruct. It is evidence
of a long trajectory under that model/scaffold, not a promise that our current
terra/Pi configuration will have the same length or performance.

## Quality And Environment Limits

The published Pandas run is **not a successful solution baseline**. Its report
has `resolved: false`, and F2P/P2P result arrays are empty. Grading logs show
pytest startup failures; the task output ends with a Pandas import-time
docstring-formatting `KeyError: "'nopython'"`. This is a failed submitted-code/
test-startup observation, not proof of a general infrastructure defect. The
long trajectory is real evidence, but its final quality score is not a clean
executed-test comparison. Our own environment baseline must be checked first.

The [official FeatureBench repository](https://github.com/LiberCoders/FeatureBench)
provides Docker images, inference and independent F2P/P2P grading. The official
fast-image list includes `libercoders/featurebench-specs_pandas-instance_15f634a6`.
However, membership of this exact task in the current fast split was not
confirmed: the dataset-server filter request failed with TLS/timeout errors.
No candidate image was pulled or tested here.

The current README announces dataset V1.1 (2026-08-24) with corrected problem
statements. The observed run dates from 2025-12. Before execution, match the
task ID, dataset version, original interfaces, image and verifier; do not assume
an unchanged current problem statement from an old trace. Pin all inputs.

FeatureBench uses its own harness and `/testbed` conventions. It is not a
drop-in DeepSWE/Pier task. Connecting Pi requires an evaluation adapter or task
wrapper, while preserving the independent verifier and excluding reference
patches from model inputs. No memory-core architecture change is implied.

## Other Sources Checked

[FeatureBench paper](https://arxiv.org/html/2602.10975) reports a default maximum
of 500 agent steps and large average cumulative token IO. A configured step cap
or million-token cumulative input alone does not prove any one context exceeds
128K; the individual trajectory above is the stronger evidence. Its README's
57.2-second fast-split figure is gold-patch evaluation time, not agent task time.

[SWE-EVO](https://github.com/SWE-EVO/SWE-EVO) is explicitly designed for
multi-version software evolution and supplies an OpenHands/SWE-agent evaluation
path. It remains a promising alternative. An inspected third-party CLI report
describes 20-minute capped runs, but also short median task times. No raw >128K
input trace was verified there during this search, so it is not ranked above
the concrete FeatureBench candidate solely because of its long-horizon label.

Official repository indexes were pinned at:

- FeatureBench: `8d4e347ec57546685c5a87e8676bf575db022ea6`.
- SWE-EVO: `9b83d5af943ba7a17567336f5b18239f73960219`.

Partial, no-checkout clones under `.artifacts/long-task-source/` were used to
list files and fetch selected documentation/trace blobs. No downloaded command,
solution or installation script was executed.

## Recommendation

Use the Pandas GroupBy task as the next **environment-validation candidate**.
First pin its task version and run a free independent environment smoke through
the intended adapter. Then consider a real 128K A/C trial with original task
instructions and no forced cut or trajectory-derived solution hints.

The previous 100-request cap can truncate a trajectory like the observed one:
its first >128K request was number 106. Trial request/time/cost allowances should
therefore be reviewed using these measurements before paid dispatch; no allowance
was increased here. The public trace's 8.35M repeated input also makes reuse of
the old USD 2 estimate unsafe without cache/pricing analysis.

This search found evidence-backed long-task material. It did not establish that
the current Pi/model pair will cross a window, that the candidate has a clean
environment locally, or that a new paid baseline is ready. No project code was
changed and no host commit was made.
