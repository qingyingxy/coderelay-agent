# CW.17.5 OS-Process Crash Recovery Evaluation

- Date: 2026-09-04
- Provider: Faux Provider
- Execution: strictly serial
- Network/API cost: none
- Result: 2/2 crash scenarios passed

## Crash Points

| Crash point | Child exit | Durable state | Recovered active window | Result |
|---|---:|---|---|---:|
| After Workflow Snapshot, before ContextWindowEntry | 86 | One Snapshot, no boundary | Old window | Pass |
| After ContextWindowEntry and active-history replacement, before continuation | 87 | One Snapshot and one boundary | New seed window | Pass |

Each scenario ran in a separate Node.js child process. The child used `process.exit()` at the target event, so normal AgentSession cleanup and promise settlement did not run. The parent then registered a fresh Faux Provider, reopened the same Session JSONL with `SessionManager.open()`, and created a new AgentSession.

## Recovery Evidence

### Snapshot committed, boundary absent

- The child exited with code 86 from the intercepted `appendContextWindow()` call.
- The Workflow Snapshot was present in the reopened JSONL, while the ContextWindowEntry count remained zero.
- Active history was rebuilt from the old window; no continuity seed or window lineage was invented.
- A new prompt completed successfully after recovery.
- The interrupted in-memory `new_context` request was not inferred or replayed, so no boundary appeared after continuation.

### Boundary committed, continuation absent

- The child exited with code 87 synchronously from `context_window_end`.
- The reopened JSONL contained one Workflow Snapshot and one ContextWindowEntry that referenced it.
- Before the resumed prompt, the active entry set contained exactly the persisted boundary seed and lineage restored at window index 1.
- The exact pre-boundary probe result was absent from active history but remained available through branch-scoped History with one hit.
- The provider response queued after the cut was never sampled or persisted.
- A new prompt completed successfully without writing a second boundary.

## Interpretation

The persisted ContextWindowEntry is the commit marker for hard-cut recovery. A Snapshot alone does not advance the window. Once the boundary exists, resume deterministically selects its frozen seed and lineage; it does not depend on whether the original process finished returning from the cut operation.

The recovery policy is intentionally at-most-once for the window request: pending runtime flags are not persisted and are not replayed after restart. The durable branch remains internally consistent at both tested points.
