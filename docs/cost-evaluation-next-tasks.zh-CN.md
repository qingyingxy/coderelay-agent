## T1：历史搜索与读取的游标一致性

依据：`src/core/history.ts` 的游标只有 action、index 和内容偏移，未绑定查询或初始结果。已复现：先搜索 alpha 取第一页，再将游标用于 beta，返回 beta 的第二条，第一条被静默跳过。

交付要求：

1. search/read 的续读游标绑定首次请求的有效查询条件及当前分支上的历史快照；search 的 query、role、tool、windowId，read 的 entryIds（含顺序）或 windowId 改变时明确拒绝。query 去首尾空白后比较，其他值精确比较。limit 和返回字节预算可改变，不属于查询身份。
2. 同一请求逐页读取完整结果，无重复、遗漏或死循环。首次请求后追加的消息和窗口不进入原分页快照；重新查询才看到新条目。正常工具调用新增日志不得导致原游标失效。
3. 切换到不包含原快照锚点的兄弟分支后，原游标明确失效，不能读取该分支之外的内容。相同分支持久化重新打开后游标仍可用，不依赖内存状态。
4. 拒绝损坏、越界、跨 action 的游标和非法 UTF-8 内容偏移；中文及多字节字符逐页拼接必须与原文一致。
5. 保持既有敏感条目过滤、search/read 返回字节限制和空结果语义。list 行为保持现状，旧版游标可明确拒绝，不要求迁移。
6. 通过现有 History 工具入口调用可完成上述 search/read 续读。对非法游标给出错误，不能伪装成成功但无结果。

允许写入（路径相对于 `packages/coding-agent`）：`src/core/history.ts`、`src/core/tools/history.ts`。其他源码、测试和配置只读。不新增数据库、语义检索、网络服务、排序功能或自动重规划。

共同验收用例：查询/过滤条件与读取目标误用；跨 action；分页完整性；追加消息与新窗口；兄弟分支；持久化重开；中文内容；非法偏移；敏感条目；正常工具续读。

## T2：截断笔记列表的分页续读

依据：`src/core/notes.ts` 的 listMemoryNotes 仅返回 notes 和 truncated；`src/core/tools/notes.ts` 的 list 不接收分页参数。已复现：8 条笔记在 800 字节预算下只返回 1 条，并标记 truncated，但无法取得其余条目。

交付要求：

1. 为 list 增加可选 limit（默认 20，整数 1–50）和 cursor；未结束时返回 nextCursor，结束时不返回。按现有 updatedAt 降序、noteId 次序排列，只列当前分支活动笔记。
2. 返回整条笔记，不截断笔记正文；整个 JSON（含游标）遵守传入字节预算。下一条笔记单独也放不下时明确报错，不能返回永远不前进的空页或静默跳过。调用方可增大预算后重试。
3. 重复使用同一游标得到同一页；逐页拼接与一次大预算列表一致，没有重复遗漏。允许续页改变 limit 和字节预算。
4. 普通消息或 list 工具日志追加不使游标失效；活动笔记集合或内容发生 upsert/archive 变化时，旧游标明确失效，调用方重新从第一页开始。持久化重开相同笔记状态后仍可续读。
5. 分支笔记状态不匹配、游标损坏、越界和非法 limit 都明确拒绝。既有 upsert、archive、来源校验及切窗提示的选择逻辑保持不变。
6. 从 Notes 工具 schema、参数映射、AgentSession 到 SessionManager 完整传递分页参数，不只实现底层函数。

允许写入：`src/core/notes.ts`、`src/core/tools/notes.ts`、`src/core/session-manager.ts`、`src/core/agent-session.ts`。后两份只允许修改 Notes 导入、类型和调用连接。测试与配置只读。

不新增笔记分类筛选、全文搜索、自动归档或新的持久化格式。不复用 T1 的实现结果：两任务分别从相同的待封存原始源码起步。

共同验收用例：默认与边界 limit；计数及字节截断；完整分页；游标重放；普通日志追加；更新与归档失效；分支切换；持久化重开；单条超预算；非法游标；真实工具参数传递。

## 两组共同协议

| 条件 | 强模型直接执行 | 强规划与快速执行 |
| --- | --- | --- |
| 模型 | sol 实现 | sol 规划、luna 实现 |
| thinking | medium | medium |
| 并发 | 一个写入者，不委派实现 | 一个 Worker；允许固定命令步骤 |
| 审查 | sol，只读，固定验收依据 | 相同 |
| 修复 | 最多一次 sol 修复，再测试与复审 | 相同 |
| 切窗 | windowed，按需使用 | 相同，不强迫切窗 |
| 数据 | 独立副本、相同原始源码和完整验收测试 | 相同 |

首次调用前，对两副本完整源码和验收文件计算 SHA-256；当前工作区有未提交修改，不能只记录 Git HEAD。任务文本和测试对两组一致，仅分工指令不同；不把规划、诊断或补丁从一组传给另一组。

候选使用正式 CLI/RPC。对照如继续使用既有外部验收适配器，必须复用相同测试命令、原始差异基线、Reviewer 输入及修复上限，并在报告注明入口差异，不宣称两个自动控制流程完全等价。适配器不可改变待测源码，不能提供人工修复提示。

计费来源：主会话统计加去重后的全部子 Agent/独立审查会话；不叠加 Task、Attempt 等汇总。保留输入、输出、缓存命中、费率、模型、失败请求记录及各阶段费用。首次失败和一次修复合并为同次任务支出；未记录 usage 的请求标为未知而非零。

缓存不人为改价，不承诺清空供应商缓存。T1 先对照后候选；T2 若启动则先候选后对照。这个次序只减少单向顺序偏差，不能消除缓存和采样差异。不能把历史参数解析结果算作新任务的对照。

## 预算与停止条件

建议额度：每次运行已记录费用达到 $1 停止，每次最长 15 分钟，最多一次修复；两任务各两组最多四次，共 $4 停止阈值。先仅安排 T1 两次，阈值合计 $2；核对质量和统计后再决定是否启动 T2，不自动批量花完。

这些是运行器观察到 usage 后的停止阈值，不是供应商硬额度，正在生成的请求可能使实际费用超出阈值。正式启动前必须验证停止与取消路径可终止当前子进程，不只终止主会话。当前文档不授权付费调用。

达到时限、费用或修复上限就记录失败并结束该次，不能重开新会话绕过上限。基础设施失败仍保留支出；本轮不自动补跑。验收需求如果事后发现遗漏，先声明该任务比较无效并停止，不现场加测试追着模型修。

结果按组报告：成功交付数/尝试数、所有尝试总费用、总费用/成功交付数（零成功则不可用），另列规划+执行和审查费用。只有一个任务两次运行时，只能说“该任务这次是否省钱”；两组同样成功才列单任务节省比例。
