# Planner 失败回退与计划证据：离线修正

## 范围与目标

本轮只做两项：核实直播分页两组的两项已知缺陷，修正对照结论；补 Planner 的失败回退与提交前证据检查。最终仍是比较完成同一任务的完整模型费用，不追加业务功能或付费试验。

## 原因与修改

原 Planner 在首轮工具调用后无条件关闭工具并要求提交计划，即使 find 失败或 grep 截断也如此。直接执行组没有这条限制，因此不能将调查差异归因于强模型或快速模型自身能力。

`planner-runtime.ts` 的 prompt 升为 planner-v3：

- 允许在配置的调查时间、总时间与轮次预算内进行后续定位和读取。部分预算配置继承 Planner 默认值，避免仅配置并发等字段时丢失调查预算。
- 依据实际工具事件识别失败、输出截断、搜索或列表数量上限，提示使用 ls/read 回退、缩小搜索或分段读取。工具仍限于 read/grep/find/ls。
- 计划的 modify/delete 目标必须有本轮成功且未报告截断的 read 记录；create 目标须有父目录列表或同目录源码读取证据。grep 命中、失败读取和模型自述不能代替源码读取。
- 证据检查在 JSON 格式修复之后执行，缺失时返回 `planner.evidence_missing`，不提交计划、不调度 Worker。新调查重置证据，预算失败的调查不能用于提交。
- 不新增业务验收项或修复轮数；保持已有单 Worker 与外部验证链路。后续真实运行允许增加必要的调查调用，其费用仍需计入任务总成本。

这是最低限度的代码依据检查，不能证明读取范围覆盖全部关键逻辑，也不能自动证明计划正确。允许针对大文件读取相关范围；接口消费者和状态入口的语义覆盖仍需要模型分析及外部验收。失败回退由宿主提示、模型选择只读工具执行；若模型不补查，宿主阻止缺证据的计划提交，不静默切换到付费强模型修复。

## 离线核实结论

两组的两个问题核实结果及费用修正见 [离线对照分析](live-pagination-cost-overhead-analysis.zh-CN.md)。sol 直接组两项均复现，sol + luna 的已有修复版本在相同场景下均正常。原始费用、测试记录和冻结代码保留。

## 验证

使用 suite harness 和 faux provider，覆盖失败 find 后 ls/read 回退、未读目标拦截、JSON 修复不能绕过、截断读取后补读、grep 数量截断提示、新建文件与证据重置，以及实际双 Agent 入口拒绝未读计划、保持零 Worker 调度。预算测试覆盖多轮只读调查、达到轮次上限后退出和监听器释放。

验证结果：4 个定向测试文件共 **31/31 通过**，`tsgo --noEmit` 通过，本次 5 个源码与测试文件的 Biome 检查通过。

全量 `npm run check` 被既有 `.artifacts/window-stage1-validation/biome.json` 嵌套 root 配置阻断，遵照用户要求不修改该配置；不能将定向检查通过写成全仓检查通过。

未调用付费模型 API；本轮无新增实验 API 费用。假模型测试不能证明真实模型在新规则下的成功率或成本收益，后续是否修业务、再做付费比较另行决定。
