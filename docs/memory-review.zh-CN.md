# 记忆整理与修订核对：可选诊断模式

## 默认路径

默认采用轻量维护：有重要变化时更新 Notes，无变化允许零写入；History 保留完整原始记录，业务 Workflow 保留执行与验证状态。整理结束或达到统一响应上限后，由宿主在工具执行结束后调用现有安全切窗 API；模型已完成切窗时不会再次切换。供应商错误、预算拒绝或超时仍报告失败，不通过宿主切窗掩盖。

默认不创建记忆核对任务、不注册 `memory_review`、不生成逐消息处置报告、不注入未完成核对索引，也没有专用的“整理＋修正＋最后切窗”阶段。不会逐请求把动态响应计数追加到系统提示。切窗完成只表示新窗口已持久化，不证明 Notes 语义完整。

维护实现位于 `packages/coding-agent/evals/context-window/notes-maintenance.ts`，当前接入 `.artifacts/memory-policy-20260918/run-C.ts` 与 `run-workflow-q4.ts`。这两个评测入口必须显式传入 `--memory-review` 才启用下述旧核对协议；`diagnostic-maintenance.ts` 保留专用修正循环。普通 CLI/SDK 原本就没有自动启用此核对器，本次没有改变其上下文阈值策略或业务验证门禁。

默认维护回执的 `dispatchAttempts` 表示调用预算包装器的尝试次数；实际供应商请求以预算账本为准。`hostCut` 区分宿主切窗与模型切窗。不启用核对时不报告 `memoryReviewComplete=true`，已有诊断任务不会被自动完成或删除。

Faux Provider 回归覆盖零写入、响应上限后的宿主切窗、写入完成后再切换、系统前缀稳定、模型提前切窗、错误及超时停止；原核对回归继续覆盖显式启用后的行为。这些是离线控制流验证，不是新的真实模型正确率或成本结果。

## 职责

- Notes：用户决定、约束、修订过程、原始来源。
- Workflow：哪些用户消息已核对，哪些核对尚未完成，检查证据。
- History：原始消息与核对报告，供缺口和后续修订查询。

实现位于 `packages/coding-agent/src/core/workflow/memory-review.ts` 与 `core/tools/memory-review.ts`。使用现有 Workflow 事件日志、Task、Attempt、Verification 和 Snapshot；没有另造任务状态存储，也不启动子 Agent。核对任务为只读，修改 Notes 仍由主任务执行。核对元数据的 usage 为0，模型调用成本由宿主主任务/评测预算统计，不能从核对任务 usage 推断模型免费。

## 已接入范围

这是宿主显式启用的协调器，仅用于可选诊断。评测入口的 `--memory-review` 或 SDK 宿主显式提供协调器才会启用。历史结果不改写；旧运行的源码哈希和协议仍以各次 manifest 为准，不把新入口的行为追溯应用到旧成绩。

启用诊断的宿主必须注册并允许 `memory_review`，在整理前对当前可见的用户消息调用 `begin`，并在每次实际模型请求上注入 `projection()`。未完成索引不占 Notes 的4000字节hint预算，而是单独的Workflow提示；额外输入有token成本。该旧诊断协议仍包含动态提示及额外响应阶段，其费用不能当作默认轻量路径的费用。

## 检查规则

每批建立独立核对 Workflow，覆盖该批全部原始用户消息ID，避免让模型自行只挑“重要修订”后再声称覆盖完整。模型提交每条消息的处置：

- `saved`：新增或修订已保存；至少一个有效Note必须引用该用户消息ID。
- `unchanged`：已有记录足够，或没有新的持久信息；必须说明理由，允许零Notes写入。
- `deferred`：尚不能确定；任务保持运行，报告与对应消息保留在History。

提交遗漏项、重复项、范围外消息、不存在的Note，或声明保存但未引用原始消息，均拒绝。全部覆盖且无deferred才完成独立的 `memory-revision-coverage` 验证，不使用 `agent-session-complete` 代替。

引用校验失败会一次列出各问题的 sourceEntryId、noteIds、原因和修正指引；失败提交不写入核对证据，也不完成任务。模型必须确认正文支持来源再补链接，不能仅贴ID通过校验；无法确认时应标记deferred。

实验宿主的响应上限分为：整理6次、存在未完成核对时修正最多3次、最后切窗机会1次。提前切窗即停止，核对已完成时跳过修正阶段；这些是上限，不是必须用满的调用数。所有实际请求仍经过原有费用预算控制，额外响应额度不会提高美元上限。最终未切窗仍报告失败，待办不自动完成；维护回执分别记录 completed、memoryReviewComplete、phaseRequests、reviewErrors 和 exhausted。预留切窗机会不保证模型一定调用成功。

切窗不会自动完成核对。即使模型没有提交报告就切窗，任务也保持未完成。后续请求注入最近5项未完成任务的短索引和总数；模型通过 `memory_review status` 获取全部范围，再按相关性查History。当前实现完整提交会重报该任务全部范围，不是局部增量提交。

## 已验证与限制

Faux Provider回归验证：缺失修订无法按saved完成；保存修订及来源后可完成；无变化可不写Note；待核对任务经过真实切窗及事件重放仍保持未完成并出现在后续请求；假来源与重复覆盖拒绝。完整5次切窗离线运行专门让模型跳过核对提交，验证运行完成与记忆核对完成可以分别记录。

这些测试验证状态与引用约束，不证明语义判断正确。模型仍可能错误使用unchanged，或把来源ID贴到语义不相符的Note；saved检查不会证明正文确实表达了决定，也没有强制每次更新保留全部旧来源。History回查仍由模型根据提示执行，不是自动查询或事实验证器。强制切窗/进程恢复后的自动接线目前仅由已接入的宿主提供，不应宣称所有产品模式都已获得此行为。

本轮未运行付费评测，不能据此更新恢复率或节省比例。
