# 三任务成本比较：离线验收与输入冻结

日期：2026-09-10。付费模型调用：0。三个原业务仓库均未修改。

后续状态：任务适配、假模型验证与 v4 可执行快照已完成，见 [执行适配报告](conversation-cost-matrix-adapters.zh-CN.md)。以下保留 v2 阶段记录；目前剩余阻断是运行进程的模型配置或认证预检未通过，不再是任务启动器未适配。

## 结论

三个候选均已证明旧代码存在目标缺口、参考实现通过当前共同验收。已冻结三种方案的相同初始输入，但尚未达到可直接启动付费比较的状态：现有启动器及权限边界仍绑定原直播控制任务，需完成任务适配和假模型验证。不得拿旧启动器直接启动新任务。

## 正反结果

| 任务 | 旧代码 | 参考实现 | 失败归因 |
| --- | --- | --- | --- |
| JobFlow 四个工作流入口 | 8/8 浏览器场景失败 | 8/8 通过 | 页面能打开并进入申请进度，但材料审核、投递记录、浏览器辅助、跟进入口缺失；桌面和手机各四项 |
| 直播状态增量与队列分页 | 原有 59 项回归通过；6 项新增后端验收失败，5 项浏览器验收失败 | 65/65 后端、5/5 浏览器通过 | 旧版缺少分页和 revision 增量协议；没有请求服务端分页，增量结果会覆盖完整状态 |
| Memory-RAG 组织权限 | 84 项既有回归通过；5 项新增 HTTP 验收失败；2 个浏览器流程失败 | 89/89 后端、2/2 浏览器流程通过 | 旧版仍是固定本地用户，匿名项目请求返回 200，注册接口不存在，登录页跳转到聊天而非提供登录流程 |

Memory-RAG 的参考提交原有 90 项测试也曾通过。最终共同集合采用 84 项既有回归 + 5 项 HTTP 行为验收，没有将依赖新增内部类的 6 项测试混入共同集合，避免旧版只因导入类名失败就终止整个测试集。

Memory-RAG HTTP 验收覆盖匿名拒绝、账号及组织角色、部门成员与项目可见性、项目成员读写边界，以及拥有者先查询后其他用户仍不能得到私有资料。浏览器在 1280×800 和 412×915 下验证登录、创建员工、建立部门、部门成员角色和项目授权，使用 API fixture。SQLite 为本轮存储验收路径；未验证 PostgreSQL 部署、外部模型质量或浏览器直连后端的完整端到端链路。通过当前验收不代表整个产品没有缺陷。

## 排查中发现的测试问题

- Memory-RAG 最初使用带 SECRET 的检索样本，命中了既有敏感信息过滤。改为普通项目交付日期数据，保留“拥有者能查到、其他用户查不到”的断言。未改业务实现。
- JobFlow 首轮由 Playwright 管理开发服务器时卡在收尾，未形成有效完整报告。改为显式启动本轮服务器、测试后关闭；最终正反测试均生成报告并退出。开发服务器均已停止。
- 这些是离线验收准备过程，不计入任何模型组费用，不作为候选模型失败。

## 比较规则与剩余工作

方案固定为 `qingyingxy/gpt-5.6-sol` 直接执行、sol 规划 + `gpt-5.6-luna` 执行、sol 规划 + `gpt-5.6-terra` 执行。共同使用 medium、一个 Worker、sol 审查、最多一次 sol 修复。保留 30 分钟无响应看门狗及重复工具结果检测，不设四分钟 Worker、十五分钟总时限或 $2 费用上限。只允许自然切窗。

成本统计包括规划、执行、上下文维护、审查、失败尝试和修复；失败费用保留。必须同时报告最终交付状态，不能把便宜但未交付写成成功交付节省。离线准备不等于付费比较结果。

剩余工作只涉及执行连接，不添加业务功能：

1. 将原直播专用启动器、写入范围和宿主测试命令适配三任务。特别是分页任务需要允许修改 `dashboard_server.py`，原直播控制边界未涵盖它；JobFlow 与 Memory-RAG 也不能套用原直播目录白名单。
2. 用假模型验证三任务权限、宿主验收、审查证据及一次修复流程；禁止读取参考实现、其他组、历史答案，禁止修改共同测试和依赖。
3. 保存新的可执行启动器快照，验证冻结任务与共同验收哈希不变，记录实际依赖及价格表，再进入付费比较。不覆盖本次冻结证据。

本轮脚本 `node --check`、根 `tsgo --noEmit`、基线与直播权限两文件共 12 项定向测试通过。`npm run check` 因既有 `.artifacts/window-stage1-validation/biome.json` 嵌套根配置失败，按此前要求暂不处理；不能将其记录为全量检查通过。
