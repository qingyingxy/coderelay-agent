# Notes 完整存储与有界目录注入

Notes 保存当前会话分支中的非权威背景、决策、约束和发现。Workflow Snapshot 仍负责执行与验证状态，History 负责原始证据。

## 预算与注入

- 模型工具单条正文上限为 32,768 UTF-8 字节，独立于 `contextManagement.notesHintMaxBytes`。
- 新窗口的 Notes 区域默认预算为 4,000 字节，按最近更新时间顺序只注入最多 5 条 Active Notes 的短目录：ID、类别、标题、更新时间和正文字节数。
- 按创建或更新的时间倒序排列；时间相同时按追加顺序倒序。读取和搜索不会刷新时间。
- Seed 不注入 Note 正文、来源正文或完整元数据。超出 5 条或预算不足时明确标记省略；所有 Active Notes 仍可通过 `list/search/read` 获取，正文只在相关任务确实需要时按 ID 读取。
- 极小预算下只给检索入口，连入口都放不下则为空。该降级不删除 Note，也不影响 History。
- 标题最多 160 UTF-8 字节，不含换行；省略时取正文开头的有界预览。可选关键词最多 16 个，每个最多 80 UTF-8 字节。

## 工具示例

```json
{"action":"upsert","note_id":"login-repro","category":"discovery","title":"登录 401 的初始复现条件","keywords":["未授权","401"],"content":"条件：access token 过期，refresh token 有效。操作：两个并发请求。观察：第二个返回 401。原因尚未确认。"}
```

```json
{"action":"search","query":"未授权","cursor":null,"category":null,"workflow_id":null,"task_id":null}
```

```json
{"action":"read","note_id":"login-repro","cursor":null}
```

`list` 与 `search` 返回索引，搜索是标题、正文、关键词上的大小写不敏感字面匹配，不是语义检索。支持 `category`、`workflow_id`、`task_id` 过滤。Seed 未注入正文或未列出索引的笔记仍可被搜索和列出。

可选参数支持显式 `null`，工具边界将其归一化为未提供。首次查询使用 `cursor=null`，无过滤条件使用 `category/workflow_id/task_id=null`；不要填写 `x`、`placeholder` 等占位值。`search` 的 query、`read/archive` 的 note_id、`upsert` 的 category/content 仍为操作必需，不能用 null 代替。无效或过期游标仍会被拒绝。

读取、列表与搜索的 JSON 输出受 `contextManagement.historyResultMaxBytes` 限制。返回 `nextCursor` 时，将它作为下一次相同请求的 `cursor`，保持过滤条件不变；读取还需保持 `note_id`。正文按 Unicode 字符边界分段，可依次拼接 `note.content`，直到 `truncated` 为 false。读取返回 `entryId` 作为版本标识，并携带来源 ID。元数据本身超过结果预算时会明确报错，需要调大该配置。

游标绑定查询条件与结果版本；更新或归档影响结果后，旧游标会被拒绝，需从第一页重新查询，避免混用版本。无关的新消息与工具调用不会使游标失效。

`upsert` 使用稳定 ID 替换整条有效笔记，不是字段补丁；更新时应提供需要保留的标题、关键词和来源。底层保留追加记录。`archive` 隐藏有效笔记，当前查询不返回归档内容，也不会跨分支读取。写入和归档的模型工具回执只返回索引，避免重复回传长正文。

## 检索与证据

先使用当前可见消息、权威 Workflow 状态与 Seed 中的 Active Notes 短目录；只有任务确实需要某条语义时，才按已知 ID 读取正文，或搜索、分页列出未显示的 Notes，必要时尝试别名。已经在当前窗口读取且没有变化的正文无需重复读取。

当前工作区是当前代码、符号、方法、文件、配置和仓库状态的权威来源。这些信息仍可从工作区重建时，必须使用 Workspace 的 read/search 工具检查，不得使用 History 定位。

必要信息齐全、没有相关未解决冲突、证据精度满足当前请求时停止检索。普通事实回答可以由 Notes 支持；仅在工作区无法重建所需的用户原话、历史决策、旧工具结果、冲突或原始证据时使用 History。知道真实原始消息 Entry ID 时优先精确读取，否则搜索。Notes 自定义存储条目不能直接当作 History 可读消息，Notes 转述也不能冒充原始引用。

直接回答所问时间范围内的定义、条件、数量或机制。不能用相关的数量或分配规则替代定义；只有解释答案所必需时才补充相邻细节，真正询问数量时则给出有依据的数量。历史用户决定依据用户消息或明确记录决定的 Notes，不能只凭实现报告推断。仅检索缺失证据，无法确认则说明未知；信息足够即停止，遵守输出格式，不输出内部检查清单。

分页仅在还需要后续内容时继续，不要求每次读完全部正文；不能根据截断结果断言信息不存在、记录完整或没有后续修订。不确定时继续取证或明确说明未知。

### 最终决定与定向检索

问题询问“最终、后来、现在”的决定时，按具体决定核对所问时间范围。如果仅有早期决定而问题涉及后续讨论，应读取相关后续 Notes；Notes 无法确认结果时再查 History。不能只看最早和最新两条而跳过相关中间修订。笔记更新时间及其中“当前、最终”的措辞仅代表该笔记记录时的状态；新笔记未提及不证明旧决定仍有效或已失效，旧决定也不会仅因时间久而自动失效。已有证据覆盖所问阶段且修订清楚时即可停止，普通事实不额外回查。

搜索围绕尚未确认的决定、条件或关系，避免仅用宽泛主题词。Notes 和 History 都是字面搜索，应选问题或可见记录中的短而有区分度的词，分别尝试别名、措辞及空格变体，不把完整自然语言问句或布尔表达式当作语义查询。查用户决定优先使用 History 的 user 角色过滤；简短同意需读取邻近提案才能解释。按真实来源 ID、窗口先后核对相关后续记录，不能把首条命中当最终结论，或把空结果当不存在修订的证明。

## 切窗前维护

正常运行不启动独立的 Notes 维护 Agent。模型在重要决策、约束、发现或未解决问题发生变化时使用现有 `upsert` 增量更新；接近边界的软提醒只要求在当前执行轮次补写尚未持久化的重要增量，不重新扫描或总结完整历史。已有记录足够时直接切窗。

`notes-maintenance.ts` 是冷启动和受控评测使用的有界整理辅助，不代表稳态产品路径，其全历史输入和费用必须单独报告。逐消息来源核对及修正循环仅通过 `--memory-review` 显式启用，详见 [可选记忆核对](memory-review.zh-CN.md)。

只保存尚未持久化的新增或变化的重要决定、约束、发现与未解决问题。已有记录足够时允许直接切窗，无需为了切窗再写一次 Notes。普通执行与验证状态继续由 Workflow Snapshot 负责。

仅更新受影响的主题，标明旧决定被何种新决定替代。upsert 仍是整条替换：更新前若看不到完整旧正文，需要读取后保留仍有效的内容、标题、关键词和来源，不能把“只记录变化”误解为仅提交一个增量正文。来源 ID 只记录实际已知值；不使用行号或虚构值。

写入策略进一步要求：

- 标题写“具体决定＋当前结论或修订”，优先使用用户语言；决定及其修订归入 decision，不把关键变化埋在批次主题列表中。
- 同一作用范围内的同一决定优先复用稳定 note_id。正文先写当前结论，再写旧决定到新决定的变化、条件、已知原因和来源。提案与已同意的决定明确区分，不混入无关主题。
- 中文对话保存相关中文检索别名，并补充有用的英文技术词或措辞变体。source_entry_ids 记录真实已知的原始消息 ID，正文说明来源支持哪项决定；未知则明确未定位，不能虚构。
- 必须另建修订笔记时，先保存新笔记取得真实 note_id，再更新旧笔记的标题和相关正文，标记被替代的决定并指向新 note_id；新笔记也注明旧笔记和修改范围。保留其他仍有效内容，不为隐藏冲突直接归档旧笔记。

修订链接是正文中的 Notes 读取指针，不是 source_entry_ids，也不是数据库外键。两次写入不是原子操作；失败时应报告链接未完成。这些是模型写入约定，系统尚不自动识别同主题、合并内容或强制创建双向链接。冻结评测 Notes 不会因此自动改写。

## 评测口径

事实恢复模式允许仅凭 Notes 回答，不强制引用原文或调用 History；普通评测输出只要求 answer，不要求 evidence 字段，也不因额外引用判失败。缺少信息、含糊或冲突时按需查询 History，信息充分即停止，暂停增加回答提示。显式证据溯源模式单独要求实际读取的原文。两者分别评分、统计费用，不合并为同一节省率。无引用要求不代表免除冻结答案的语义核验，旧报告仍保留当时的格式判分。

候选提示与评测位于 `.artifacts/memory-policy-20260918/`。六题固定快照对照为旧提示6/6、新提示5/6，恢复费用低13.15%，质量门槛未通过。逐项核对后的单题重放仍失败；最终决定核对与定向检索的三题回归为2/3，原失败题仍漏查修订。此后补充的主题笔记写入约定尚未经过真实模型验证；旧实验脚本、冻结 Notes 和结果保留。完整流程与固定快照评测不能混用费用口径。

检索提示不强制模型执行搜索。离线测试验证存取、分页、预算和跨窗工具链；真实模型是否主动找回信息，还需另行评测。
