## 历史恢复：测了什么

对照组使用 Pi 原生 `session.compact()`；候选组使用 `new_context` 切窗并通过 `history` 查回原文。每段完成的对话经历五次强制维护，最后一次性提问，问题与答案不进入维护输入。使用配置模型 `qingyingxy/gpt-5.6-terra`、medium；完整参数见原报告。

- 候选组的 50 项语义回答均有实际返回的历史原文支持，由人工按预先确定的答案评分。
- 对照组只完成 4/7 段对话，回答正确 11/26 项；另 24 项因维护请求超时未测，不能算作回答错误。
- 在双方都完成的四段对话中，候选组为 26/26，对照组为 11/26。这一子集存在筛选偏差。
- 仅 29 项事实跨越五次维护，其余跨越一至四次，且可能被后续重复提及。不能表述为“50 项事实均完整跨越五次切窗”。

这是历史信息回查实验，不能直接证明复杂编程任务完成率提高，也不能保证模型交接不会遗漏需求。原始对话、问题、答案和逐项判定未公开，因此外部读者可查看汇总方法与结果，但不能独立复算全部评分。

## 模型分工：成功与失败一起看

三任务矩阵比较 sol 直接执行、sol 规划 + luna 执行、sol 规划 + terra 执行。同任务内固定初始代码、共同测试、审查标准和一次修复上限；各组均包含 sol 独立审查。模型名称为实验配置标识，单价见原报告。

JobFlow 的三组都完成交付，但 Memory 和该轮直播分页的三组均未达到交付门槛，各方案总体均为 1/3。失败支出保留在原报告中，不能只看便宜的成功样本就推断模型分工普遍更省。

直播分页的 55.3% 属于后续跨版本比较：候选组约 27 分 38 秒，已有直接组约 15 分 49 秒。前一次候选失败的已知费用 $0.4147296 未计入本次成功运行；合计已知支出至少 $1.20593252，另有取消请求用量未知。它不属于前述九组同任务比较，也不适合作为一般节省率。

## 可以直接运行的公开样例

仓库提供无需模型密钥的配置读取演示：真实写入代码、运行 Node 测试，在一次切窗后保留待办，按需找回失败证据并修复。模型回复与修复方案预设，用来检查接续链路；它不会复现上面的真实模型评分或费用。

需要 Node.js 22.19 或更新版本，从仓库根目录运行：

```powershell
npm install --ignore-scripts
npm run hydrate:model-data
npx tsx packages/coding-agent/examples/sdk/25-config-workflow-demo.ts
```

首次安装和模型目录元数据初始化需要联网，之后演示本身离线运行。预期测试从 2/3 到 3/3 通过，最终输出 `[demo] PASS`。详见[演示说明](cli-agent-showcase.md)和[演示源码](../packages/coding-agent/examples/sdk/25-config-workflow-demo.ts)。
