## 已落实的边界

三个副本各自从同一修复前版本开始，共同验收仍是原来的 59 项后端测试和 5 个浏览器场景。

- 模型可读取本组副本和指定依赖；相关业务源码允许修改，不再限定历史修复的四个文件。
- 测试、依赖清单、锁文件、构建配置和其他项目禁止修改。Planner、Reviewer 不可修改业务源码。
- 文件访问在工具调用之前检查真实路径；覆盖父目录穿越、跨组绝对路径、链接绕过、Windows 特殊路径以及 `@`、`~` 简写。
- 关闭模型任意 shell 调用，固定验收交给外部执行器。关闭自动发现上下文文件、扩展、技能和提示模板，只显式加载本次边界扩展。
- 外部验收使用模拟直播/Unity 接口，并非真实直播间。文件工具约束不等同于外部测试代码的操作系统沙箱。

11 项权限/RPC 专项测试通过，TypeScript 检查通过。规划、执行和修复会话共 142 次已记录工具请求按最终边界回查，没有发现超范围请求；三组副本的受保护文件清单与内容均未改变。Reviewer 使用同一只读边界，但此回查不包含未持久化的 Reviewer 逐条读取记录。

## 离线修复验证

2026-09-10 后续检查，新增付费 API 调用为 0，未修改直播业务代码或共同验收。

- 建议分类：新增代码中的可选清理或加固不再因 `introducedByChange: true` 被升级为用户确认。需求违反、行为回归、安全及真正待决事项仍保留原来的阻断规则。
- Reviewer 名额：审查调用在退出时释放自己创建的 Agent，包括重试 Agent；保留交接和用量记录。
- RPC 租约：原来的 `stop()` 直接终止子进程，离线复现了子进程退出后 Direct 工作流租约仍存在。现改为先通过已有的有界 abort 流程让子会话清理，再终止进程。修复后，主动停止及审查超时重试均未遗留租约。

52 项相关测试通过，TypeScript 和本次文件的 Biome 检查通过。仓库总检查仍受上文已有嵌套配置阻断。

离线闭环使用 faux provider、真实文件写入与 Node 子进程验收，验证单 Agent 名额下的“执行失败 → 审查 → 一次修复 → 复测 → 复审”：修复成功则交付，修复仍失败则停止，不创建第二次修复。DiffCollector 在该生命周期测试中使用桩，不将其视为真实项目差异收集的端到端验收。另以实际 CLI/RPC 子进程验证超时后的审查重试。

对应测试：`test/workflow/review-protocol.test.ts`、`test/suite/delivery-review-lifecycle.test.ts`、`test/suite/reviewer-rpc-cleanup.test.ts`。本次覆盖可响应 abort 的退出路径，不声称解决操作系统强杀或子进程彻底失去响应后的所有租约恢复问题；也不改变此前三组未成功交付的结果。
