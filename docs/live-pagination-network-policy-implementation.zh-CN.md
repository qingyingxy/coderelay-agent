# 停止规则与网络重试：离线落实

> 后续真实入口复测更正：执行器自身不再补默认值，但 `WorkflowController.startPlan` 仍将 Profile 的 240 秒/12 轮默认预算注入根任务，实际入口仍会被截断。此前离线用例未覆盖这条预算传递链，不能据此宣称入口已完整修好。详见 `live-pagination-network-pair-20260911.zh-CN.md`。

本次只修改框架与成本比较适配器，没有修改直播业务、重新冻结历史记录或调用付费 API。最终目标仍是同一旧代码基线、同一验收和一次修复上限下，比较 sol 直接与 sol 规划加 luna 执行的完整费用。

## 已落实

- Planner 不再隐式应用 90 秒调查截止、240 秒总时长和 12 轮上限。默认沿用 30 分钟无活动、重复结果检测；调用方明确传入的时间和轮数限制仍有效。JSON 格式修复也有无活动监控。
- 调查最后一次请求失败或取消时，直接标为调查失败，不把旧输出当作完成的计划再进入 JSON 修复。
- 双 Agent SDK 入口、RPC 子进程、进程内子 Agent 和比较器两组主会话均使用两次外层重试，等待 2 秒、4 秒。底层 provider 自动重试为 0，避免重试次数相乘。网络重试不消耗业务修复次数。
- 复用现有临时故障分类；认证、额度不足和取消不重试。已完成的工具结果保留，不从任务起点重跑。
- 会话记录模型尝试起止时间、轮次、重试次数、收到响应头的时间、有效超时配置、已知费用和用量是否可确认。Planner 和评测宿主主动停止会留下原因记录。
- 比较器父子会话共同写入请求审计文件，生成 `request-accounting.json`；只要存在未知用量，就标为费用下界。失败尝试已返回的费用仍由原有累计统计纳入，诊断记录不重复加费。

## 证据边界

计时从 assistant 开始到结束，包含本地请求准备，不是 TCP 抓包时间。响应头时间来自 provider 回调。归一化的错误消息不保留 SDK 原始异常链，因此异常类型和底层原因码记为 null，不能据此断言 DNS、TCP、TLS 或代理故障。只有有本地主动停止证据的取消才归因到 Planner/宿主，其余取消来源标为未知。

零 token 记录保守视为用量未知，即使它可能确实未收费；部分返回的 usage 也不等同于供应商最终账单。此次不修改底层连接超时，不把旧失败试验重新解释为成功交付。

## 验证与后续

使用假时钟、faux provider 和本地 RPC 假子进程验证进展超过旧时间/轮数限制、停滞取消、显式预算、JSON 修复清理、两次重试上限、取消不重试、成功工具不重放、失败费用保留，以及父子入口统一配置。无付费网络请求。

最终结果：8 个定向测试文件、79 项测试通过；独立 TypeScript、9 个修改文件的 Biome 检查和两个评测脚本的语法检查通过。

完整 `npm run check` 仍受既有 `.artifacts/window-stage1-validation/biome.json` 嵌套根配置阻塞，按用户要求未处理。独立 TypeScript 和修改范围内的 Biome 检查另行执行。

下一次付费比较前需要重新冻结包含本次改动的框架和相同业务基线。此前冻结目录与费用记录保持原样。

## 真实入口预算链修正（后续离线回归）

已从 `BUILTIN_AGENT_PROFILES.planner.defaultBudget` 移除 `maxDurationMs: 240_000` 和 `maxTurns: 12`，保留原有隔离与重试约束。这样 `WorkflowController.startPlan` 无法再把这两个默认硬限制注入根任务；调用方明确设置的预算仍按原继承规则传递。未修改其他角色预算、业务代码、冻结副本或历史费用。

新增 `test/suite/planner-budget-entry.test.ts`，通过 `createPlannerExecutorSession` 和评测实际使用的 `createAgentSession + enableWorkflowTracking` 两个入口调用 `session.prompt`，不直接调用或替换 Planner 执行器、Controller 或预算继承函数。工具读取真实临时文件，模型为 faux provider，时间由假时钟推进。

- 修正前：12 项测试中 8 项失败，准确复现隐含 240 秒/12 轮截断；即使显式设置 600 秒/32 轮，也被旧默认值压低。

- 原有角色、计划创建、预算继承、Planner 证据和看门狗相关测试 66/66 通过，合计 78 项。独立 TypeScript 与本次修改文件的 Biome 检查通过；全仓检查仍被既有嵌套 Biome 配置阻塞。

本次没有调用付费 API。结论仅是新建 Workflow 的 Planner 预算传递链已通过离线真实入口回归，不代表重新完成了两组交付成本比较；已有冻结版本和已持久化的旧任务预算不被追溯重写。
