## 时间预算的比较限制

三组外层协议均为 $2 软费用阈值、15 分钟总上限、最多一次 sol 修复，但实际执行阶段上限并不对称：

- Plan runtime 的 `taskAttemptBudget` 对首次 Worker 应用 `MAXIMUM_INITIAL_WORKER_MS = 240_000`，为后续验证与修复留时间。
- luna、terra 的实际 Agent budget 均为 240000ms；luna 在该限制内返回，terra 超时退出。
- sol 直接执行没有相同的独立首次 Worker 上限，运行到修复阶段才耗尽整个 15 分钟预算。

出处：冻结框架 `packages/coding-agent/src/core/workflow/plan-runtime.ts:95`、`:130`，以及各组 `report.json` 内的 Agent budget。Worker profile 默认 900000ms 不是最终生效值；仅核对外层协议和 profile 不足以证明公平。

**预检没有核对到这一层生效预算，是本轮准备遗漏。** 本轮可以反映当前框架策略下的费用与失败情况，不能把差异完全归因于模型分工。没有为补救这一问题中途改框架或延长某组时间。
